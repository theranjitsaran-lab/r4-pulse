Data states for R4 Pulse

Every data block on every screen, in loading, empty, error and stale. "Built" means the app does this today, in the words shown. "Spec" means it is designed here and not built.

12 screens and 51 data blocks. Of their 102 empty and error states, 32 are built and 70 are specs. Nothing on this page changes the app.

The four states

Loading

Built, once per screen, in public/app.js: grey shapes where the page will be, no spinner, still under reduced motion. Blocks that share a data call load together, so they share it.

Empty

No postcodes on done orders in this window.

A dashed border and one line saying what belongs here. Never a zero or an invented figure. A table with no rows left after filtering stays a plain row: "Nothing matches these filters."

Error

This screen did not loadIts figures are not available just now. Try again in a minute.

Built, once per screen. What broke and what to do, never the raw error. One failed call takes down every block that uses it.

Stale

Data to Fri, 30 Oct: late, Veri-Shred has sent no finished work since then

Built, for the whole app, in the bar under the masthead. Figures stay on screen as of that date.

Stale: one rule for every block

  • The bar under the masthead, on every screen. It turns amber when the latest finished work is older than the last working day (freshStamp, public/components/metrics.js).
  • Operations, and the old Home at #classic. A sentence is added when the data is more than two days old.
  • No block has its own stale state. All the figures come from the same nightly refresh, so a block-by-block warning would repeat the same fact. Today has no sentence of its own, only the bar.
  • VCK's invoices can move on separately. Today and Money show the difference, for example "VCK now holds $638K: $6K posted since this was built".

Loading and error: one rule per data call

Most blocks share a call with their screen, so they load and fail together. The table says "Screen error" for those. To make a block fail on its own, its call would need splitting, which changes the server and was decided against for this work.
